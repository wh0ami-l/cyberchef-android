# 发布指南

这份文档说明怎么把这个 Android 移植版发布到自己的 GitHub 仓库。

> ⚠️ **发布前先看完第 1 节。**签名密钥如果进了公开仓库，任何人都能签出会被
> Android 当作「可信升级」安装的 APK。

---

## 1. 密钥（最重要）

### 为什么危险

Android 靠 **包名 + 签名密钥** 判断一个 APK 是不是某个已安装应用的合法升级。
两者都对上，系统就静默安装，用户看不到任何提示。

所以如果 `.jks` 私钥和密码都在公开仓库里，攻击者可以：

1. 用同一个密钥签一个带恶意代码的 APK
2. 已安装你这个 App 的用户，会把它当成正常更新装上

这是一条完整的供应链攻击路径，不是理论风险。

### 本仓库的做法

- `android/keystore/` 和 `android/keystore.properties` 都在 `.gitignore` 里
- 密码不在 `build.gradle` 里，而是从 `keystore.properties` 或环境变量读
- 生成密钥用 `scripts/make-keystore.sh`，它会生成 28 位随机密码

### 发布前自检

```bash
git check-ignore -v android/keystore.properties android/keystore/cyberchef-release.jks
```

两条都应该有输出（表示被忽略）。**没有输出就绝对不要 push。**

### 备份密码

密钥丢了，你就再也发不出能被老用户升级的新版本。把密码存进密码管理器，
并且：

```bash
base64 -w0 android/keystore/cyberchef-release.jks   # 存成 GitHub Secret: KEYSTORE_BASE64
```

在仓库的 **Settings → Secrets and variables → Actions** 里加三个 secret：

| Secret | 内容 |
| --- | --- |
| `KEYSTORE_BASE64` | 上面那条命令的输出 |
| `KEYSTORE_PASSWORD` | `keystore.properties` 里的 `storePassword` |
| `KEY_PASSWORD` | 同上（默认两者相同） |

### 关于换密钥

换密钥后，**已安装旧版的用户必须先卸载**才能装新版——签名不同，Android 拒绝覆盖。
所以要在第一次公开发布之前换好。

## 2. 首次推送到 GitHub

```bash
cd <仓库目录>
git init
git add .
git status              # 确认没有 keystore、没有 www/、没有 node_modules

# 再确认一次体积，应该是几百 KB 而不是几个 GB
git ls-files --others --exclude-standard | wc -l
du -ch $(git ls-files --others --exclude-standard) | tail -1

git commit -m "CyberChef for Android: unofficial port"
git branch -M main
git remote add origin git@github.com:<你的用户名>/<仓库名>.git
git push -u origin main
```

`.gitignore` 已经排除了这些（当前仓库应为 **66 个文件、约 480 KB**）：

| 排除项 | 原因 |
| --- | --- |
| `CyberChef/` | 上游完整仓库，含 4500+ 提交历史；由 `bootstrap.sh` 按 `CYBERCHEF_VERSION` 拉取 |
| `android/app/src/main/assets/www/` | 由 `package-web.mjs` 生成，约 58 MB |
| `sdk/`、`toolchain/`、`.gradle/` | 本机工具链，约 1.7 GB |
| `**/build/`、`dsdex/`、`.build-tmp/` | 构建产物 |
| `android/keystore*` | **密钥** |
| `android/local.properties` | 含本机绝对路径 |
| `*.apk` | 走 GitHub Releases |

## 3. 发布一个版本

### 手动

```bash
# 1. 改版本号
#    android/app/build.gradle  ->  versionCode / versionName
git commit -am "release v11.5.0"
git tag v11.5.0
git push origin main --tags
```

推 tag 会触发 `.github/workflows/release.yml`，它会：

1. 拉取 `CYBERCHEF_VERSION` 指定的上游版本并构建 web bundle
2. 用仓库 secrets 里的密钥签名
3. `apksigner verify` 验证签名
4. 生成 `.sha256`
5. 把 APK 和校验和挂到 GitHub Release

### 本地出包

```bash
scripts/build-apk.sh
# -> CyberChef-app-release.apk
sha256sum CyberChef-app-release.apk > CyberChef-app-release.apk.sha256
```

然后到仓库的 **Releases → Draft a new release**，把两个文件拖进去。

> **不要把 APK 提交进 git。**26 MB 的二进制会让每次改动都让历史翻倍，
> clone 会变得非常慢。Releases 的附件就是干这个用的。

## 4. Release 说明里该写什么

至少包含：

```markdown
Unofficial Android port of CyberChef 11.5.0.

- 基于上游 CyberChef v11.5.0（commit ae4617c）
- 移动端适配：分屏可调工作区、触屏操作、文件保存
- minSdk 26 / targetSdk 35

**非官方版本**，与 GCHQ 及 CyberChef 维护者无关。
CyberChef 采用 Apache License 2.0，详见 NOTICE 与 LICENSE。

安装前请用附带的 .sha256 校验下载文件。
```

## 5. 让别人能编译

别人 clone 下来只需要：

```bash
scripts/bootstrap.sh    # 装工具链 + 拉上游 + 构建 web + 生成密钥
scripts/build-apk.sh    # 出 APK
```

`bootstrap.sh` 是幂等的，重复跑不会重复下载。它会把 JDK / Gradle / Android SDK
都装进仓库目录内，不污染系统，也不需要 `sudo`。

需要宿主预先装好：`git`、`node`（>=24 <27）、`npm`、`curl`、`unzip`。

| 你新增的部分 | 版权归你，建议同样用 Apache-2.0 |
| 商标 | Apache-2.0 第 6 条**不授予**商标权 |

义务（Apache-2.0 §4）：

- ✅ 附带许可证全文 → `LICENSE`
- ✅ 保留版权声明 → 上游源码与 webpack 产出的 `*.LICENSE.txt` 都原样保留
- ✅ 声明你做过的修改 → `NOTICE`
- 上游没有 NOTICE 文件，所以无需传递 NOTICE

**非官方声明**已经放在 `README.md` 顶部和 `NOTICE` 里。"CyberChef" 是 GCHQ 的
项目名，说明清楚"非官方"既是礼貌，也是商标上安全的做法。

如果想要更保险，可以把应用显示名改成 `CyberChef Mobile (unofficial)`——
改 `android/app/src/main/res/values/strings.xml` 的 `app_name` 即可，代价是桌面
图标下的文字会被截断。
